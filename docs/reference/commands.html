Command definitions and what a command callback gets.

#

A command run on the client that typed it (Registry::client_command), never sent.

  • .client() -> crate::Client source

#

What every command gets: its arguments and a way to answer.

  • .player() -> u64Entity id of the player who ran the command. source
  • .int(name: &str) -> Option<i64> source
  • .float(name: &str) -> Option<f64> source
  • .text(name: &str) -> Option<&str>Words, text, player names, and the full names of items, blocks, entities, dimensions, attributes. source
  • .id(name: &str) -> Option<u32>Registry id of an item, block state, entity kind, dimension or attribute parameter. source
  • .targets(name: &str) -> Vec<u64>Entities a targets parameter selected (@e[type=zombie], a player name, ...). source
  • .pos(name: &str) -> Option<Vec3> source
  • .given(name: &str) -> boolWhether a literal word of the usage (or an optional parameter) was given. source
  • .reply(key: &str, args: &[crate::Arg])A line for whoever ran the command: the translation key with args, formatted by their client in its own language. Call again for more lines. source

#

What Registry::command gives back, to say more about the command.

  • .permission(level: u32)The abi::permission level it asks for. source

#

A command run on the server (Registry::command).

  • .world() -> WorldThe world it runs in. What it changes settles when it returns (neighbors, events). source
